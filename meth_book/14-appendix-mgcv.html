14.1 Executive summary: polynomials, splines, and tensor products

Real biomedical relationships are rarely straight lines. Risk often rises gently, then steeply; dose–response curves plateau; effects of age bend at midlife. To fit such patterns we need models that can bend, and the choice of how to let them bend is an important decision in model building.

Polynomials bend globally. Adding squared and cubed terms to a regression lets the fit curve, and for mild curvature this works. The catch is that every part of the curve depends on every data point: a cluster of observations at one end of the x-range can tip the fitted line at the other end. Higher-degree polynomials oscillate near the boundaries and extrapolate badly. They are a blunt instrument.

Splines bend locally. A spline is built from many small, overlapping pieces, each active only in a narrow region of x. Wiggle introduced by a cluster of points stays where it belongs. Splines fit complex shapes — thresholds, plateaus, U-shapes — without disturbing parts of the curve where the data are well-behaved. This is the workhorse of modern flexible regression.

Penalized splines — the kind mgcv fits – allow plenty of flexibility, then penalize wiggliness, and let the data decide how much curvature to keep. The smoothing parameter is selected automatically (REML or GCV). Practically, you stop asking “how many knots?” and start asking “how wiggly should this be?” — and the algorithm answers.

Reach for s() first. In mgcv, s(x) fits a penalized thin plate spline — a sensible default for one covariate, and the building block for most GAMs you will write. For a smooth surface in two covariates that share a scale (latitude and longitude, two anatomical coordinates), s(x, z) works directly.

Reach for te() or ti() when scales differ or interactions matter. When you want a smooth interaction between covariates measured in different units — age in years and dose in mg, for example — use a tensor product smooth, te(x, z). It builds the surface from separate one-dimensional smooths in each direction, with a separate amount of smoothing for each, so rescaling one covariate does not distort the fit. Use ti() when you want to separate the interaction from the main effects, ANOVA-style: s(x) + s(z) + ti(x, z).

te() & ti() give practically identical predictions with marginaleffects. However, the models are not exactly identical, differing in their penalty structure, not their basis.

te(x, z) has one smooth term with two smoothing parameters (one per marginal direction) applied to the joint tensor product basis. Main-effect and interaction parts of the surface share those penalties. s(x) + s(z) + ti(x, z) has three smooth terms with their own smoothing parameters — so the main effect of x, the main effect of z, and the pure interaction surface are each shrunk independently.

When signal is weak, the data are noisy, or one component is much smoother than the other, the s() + s() + ti() decomposition can shrink the interaction more aggressively and pull the predicted surface visibly toward additivity. That is a feature, not a bug. In addition, with ti(), you get a separate coefficient for the pure interaction, which is what you want if the question is “is there an interaction beyond the additive main effects?”. With te(), you cannot separate that question from “is there any joint effect at all?”

For marginaleffects-driven plots, there is little reason to write the three-term form. Reach for s(x) + s(z) + ti(x, z) when you specifically want each piece to have its own penalty — for instance, when you suspect strong main effects but only mild interaction and want the model to lean that way.

Start with s() per covariate. Add te() or ti() only when an interaction is biologically plausible and you have enough data to estimate it. Let the penalty handle wiggliness. Inspect each smooth visually before trusting it.

14.2 From polynomials to splines: a more technical exposition

A polynomial regression model is the simplest way to let the conditional mean of y bend with x:

\[E(y \mid x) = \beta_0 + \beta_1 x + \beta_2 x^2 + \cdots + \beta_p x^p\]

This is a basis expansion: we write the unknown function f(x) as a sum of known building blocks — here, the powers 1, x, x². The model is linear in β even though it is nonlinear in x.

“Linear in β” means that if we fix the data and view the fitted value as a function of the coefficients, doubling every β doubles every fitted value, and the contributions of β₀, β₁, β₂, … add up. Concretely, define new variables z₁ = x, z₂ = x², z₃ = x³, and so on. Then

\[E(y \mid x) = \beta_0 + \beta_1 z_1 + \beta_2 z_2 + \beta_3 z_3 + \cdots\]

is an ordinary multiple linear regression, with the zⱼ playing the role of predictors. The relationship between y and the original x is curved — that’s the whole point — but the relationship between y and the constructed columns zⱼ is a flat hyperplane.

This is not a notational trick; it has three concrete consequences.

Estimation is a solved problem. Because the model is linear in β, the coefficients are obtained by ordinary least squares. The same is true for splines, which is why these methods are fast and stable on large datasets.

Inference carries over. Confidence intervals for nested models rely on linearity in the parameters, not linearity in the predictors. For polynomial and spline models, the toolkit of linear-model inference applies unchanged. (Penalization complicates this slightly — the penalty shrinks β toward zero, so frequentist standard errors get a Bayesian reinterpretation in mgcv — but the underlying machinery is still linear.)

Note

Into a linear model the parameters enter linearly; the predictors can be raw covariates, polynomial powers, log transformations, dummy variables, interaction terms, or spline basis functions. In truly nonlinear models, the parameters appear inside an exponential, a ratio, or a custom mechanistic equation.

Polynomials have well-known weaknesses. They are global: every coefficient depends on every observation, so a few points at one end of the x-range can pull the fitted curve at the other end. High-degree polynomials oscillate badly between data points. Increasing the polynomial degree to capture local detail tends to make the global fit worse, not better. Splines fix this by replacing the global building blocks with local ones. A regression spline still has the form

\[f(x) = \sum_{j=1}^{k} \beta_j \, b_j(x),\]

but each bⱼ(x) is a piecewise polynomial — typically cubic — that is non-zero only over a small range of x. The pieces are joined at locations called knots with continuity in the function and its first two derivatives, so the result is visually smooth. Because each basis function has local support, adding a knot in one region does not perturb the fit far away.

A practical question becomes: how many knots, and where? The penalized spline approach sidesteps this by using more knots than strictly needed and adding a wiggliness penalty to the objective:

\[\text{minimize} \quad \sum_{i=1}^{n}\bigl(y_i - f(x_i)\bigr)^2 \; + \; \lambda \int f''(x)^2 \, dx.\]

The first term rewards fit; the second penalizes curvature. The smoothing parameter λ controls the trade-off and is chosen automatically — by REML or GCV — inside mgcv. Ordinary polynomial regression is then just the simplest, unpenalized, global case of this framework.

14.2.1 Thin plate splines: the default for s() in mgcv

When you write s(x) in mgcv, you get a thin plate regression spline by default. The thin plate spline (TPS) is the natural multivariate generalization of the cubic smoothing spline: among all smooth functions of d variables passing close to the data, it minimizes an integrated-squared-second-derivative penalty. In two dimensions the penalty is

\[\iint \bigl( f_{xx}^2 + 2 f_{xy}^2 + f_{yy}^2 \bigr) \, dx \, dy,\]

which is — literally — the bending energy of a thin metal plate forced through the data points. Hence the name.

TPS does not require the analyst to choose knot locations; in its original form it places one basis function at every data point, with the smoothing penalty doing the regularization. Wood’s thin plate regression spline is a low-rank truncation that keeps the most informative basis functions and discards the rest, giving essentially the same statistical behaviour at a fraction of the cost. The TPS penalty is isotropic: it treats all input directions equivalently. For a single covariate this is harmless, but with several covariates passed into one smooth — s(x, z) — isotropy means the same notion of wiggliness is applied to both, which is sensible only when x and z are on comparable scales (latitude and longitude, say, but not age in years and dose in milligrams).

14.2.2 Tensor product smooths: a different construction

When covariates are on different scales or play qualitatively different roles, mgcv offers tensor product smooths via te() and ti(). These are built differently from TPS. The key point is the penalty: each marginal direction gets its own smoothing parameter and its own penalty, so smoothness in x is regulated independently of smoothness in z. The fit is therefore invariant to rescaling either covariate. te(x, z) builds the full smooth (interaction plus marginals); ti(x, z) strips out the marginal main effects, which is the right choice when you want an ANOVA-style decomposition s(x) + s(z) + ti(x, z).

A useful rule of thumb: use s() for one covariate, or for several covariates on the same scale; use te() or ti() for multidimensional smooths on different scales, and for testing interactions.

Figure 14.1. From global polynomials to local, penalised splines.

(A) A polynomial basis of degree three over the interval [0, 1]: the constant, x, x², and x³. Each basis function is non-zero across the entire range of x, so the fitted coefficient on any one term influences the fitted curve everywhere. This is what is meant by a global basis. (B) A cubic B-spline basis on the same interval, defined by six interior knots evenly spaced across [0, 1]. Each basis function is a localized bump, non-zero only over a narrow neighbourhood of x. Changing the coefficient on one bump perturbs the fitted curve only in that neighbourhood; this is a local basis. (C) Three fits to the same simulated dataset (n = 120; true mean function f(x) = sin(2πx) + 0.5x; Gaussian noise, σ = 0.35). Grey points are the simulated observations. The dashed line is a degree-15 polynomial fitted by ordinary least squares; note the visible oscillation near x = 0 and x = 1 (this is boundary oscillation typical of high-degree polynomials). The dotted line is an unpenalised cubic regression spline with 20 basis functions, which tracks individual data points between knots. The solid red line is a penalised thin plate regression spline (s(x, bs = "tp", k = 20)) with the smoothing parameter λ chosen automatically by REML; it recovers the underlying smooth signal without chasing the noise. (D) The same thin plate spline as in panel C, but with λ fixed by hand at four contrasting values, from heavy penalisation (λ = 100) to almost none (λ = 10⁻⁵). With large λ the wiggliness penalty dominates and the fit collapses toward a straight line (over-smoothing); with small λ the penalty is negligible and the curve follows individual observations (under-smoothing). The dashed grey curve, identical across facets, is the REML-chosen fit from panel C and serves as a reference for the data-driven choice. Together, panels A–D show that splines extend polynomial regression by replacing global building blocks with local ones, and that the smoothing parameter — not the number of knots — is the practical dial controlling model complexity.

First model: s(x) fits a penalized smooth of one variable. The default basis is bs="tp" (thin-plate regression spline). One variable, one smoothing parameter (λ), one penalty on wiggliness.

Show code 
library(marginaleffects)
m1 <- gam(y ~ tx + s(age, by=tx) + s(bmi, by=tx), data = dat, method = "REML")
plot_predictions(m1, condition = c("age", "tx", "bmi"))

You can write s(age, bmi) — but this is a 2-D isotropic thin-plate smooth: it assumes age and BMI are measured on the same scale and uses a single λ for combined wiggliness in both directions. That’s almost never appropriate when the variables have different units. A change of 1 year and 1 kg/m² are treated as equivalent distances.

Show code 
# OK only if x1 and x2 are on the same scale (e.g., spatial coordinates lat/lon)
m_iso <- gam(y ~ tx + s(age, bmi, by=tx), data = dat, method = "REML")
plot_predictions(m_iso, condition = c("age", "tx", "bmi"))

Better model: te(x1, x2) builds marginal smooths separately and combines them via a tensor product. Each margin gets its own smoothing parameter, so the fit is invariant to rescaling the inputs.

Show code 
m2 <- gam(y ~ tx + te(age, bmi, by=tx), data = dat, method = "REML")
plot_predictions(m2, condition = c("age", "tx", "bmi"))

lets add categorical predictors

Show code 
m2.1 <- gam(y ~ te(age, bmi, by=tx) + tx + sex + s(region, bs = "re"),
          data = dat, method = "REML")
plot_predictions(m2.1, condition = c("age", "tx", "bmi"))

te(age, bmi) here covers:

  • the main effect of age,
  • the main effect of bmi,
  • and their interaction — all in a single term, with two λs (one per margin).
Note

You can specify per-margin bases and basis sizes, e.g. te(age, bmi, bs = c("cr","cr"), k = c(10, 10)). Good catch — bs = "cr" slipped in there without explanation. Here’s what it does. bs (“basis”) tells s(), te(), or ti() which kind of spline basis to build the smooth from. mgcv offers many; the three you will meet first are: - bs = "tp" — thin plate regression spline. The default for s(). No knots to choose; mgcv picks an optimal low-rank basis from the data. - bs = "cr" — cubic regression spline. A classical penalised cubic spline with knots placed at quantiles of the covariate (or evenly, if you specify). Each basis function is a piecewise cubic, joined smoothly at the knots. - bs = "re" — random effect. Not a smoother in the usual sense; treats the levels of a factor as draws from a Normal distribution, exactly as in a mixed model. That is why s(region, bs = "re") appears in your m2 call — it is a random intercept for region, not a smooth curve over region.

te() builds its joint basis as a tensor product of marginal one-dimensional bases — one per input. The bs argument inside te() lets you pick what those marginal bases are. bs = c("cr", "cr") says: use a cubic regression spline for the age margin, and a cubic regression spline for the bmi margin. There are two practical reasons to prefer "cr" over the default "tp" here: (i) it is much cheaper to compute. (ii) It fits the geometry of te() better. Tensor products already give each margin its own smoothing parameter, which is the whole point of using te() over s() for variables on different scales. The optimality argument behind thin plate splines is isotropic — it assumes a single common notion of wiggliness across all inputs — and that argument doesn’t apply once you have separated the margins. So you lose nothing conceptual by switching to "cr", and you gain speed. What k = c(10, 10) does?k is the basis dimension — the upper bound on how wiggly each margin is allowed to be before the penalty kicks in. k = c(10, 10) means up to 10 cubic-spline basis functions for age and 10 for bmi, giving the joint surface up to 10 × 10 = 100 coefficients before penalisation. The penalty then shrinks the effective dimension down to whatever the data support; you check whether k was set high enough using gam.check() or k.check(). In plain Englishte(age, bmi, bs = c("cr","cr"), k = c(10, 10)) says:

Build a smooth surface of age and bmi by taking cubic regression splines in each direction (10 basis functions each), forming all 100 pairwise products, and letting REML pick a separate smoothing parameter for the age direction and the bmi direction.

It is the same model class as te(age, bmi) — same function space, same interpretation — just with explicit, faster marginal bases.

If you want main-effects-plus-interaction with separable terms (e.g., for testing interaction significance, or to keep the main-effect smooths interpretable in plots), use ti():

Show code 
m3 <- gam(y ~ tx + s(age) + s(bmi) + ti(age, bmi) +
              sex + s(region, bs = "re"),
          data = dat, method = "REML")
plot_predictions(m3, condition = c("age", "tx", "bmi"))

This says: tx shifts the entire response surface up or down by a constant amount, the same shift at every age, every bmi, every region. The treatment effect is one number — the coefficient on tx — and it is the average treatment effect on the response scale (or log-scale if you used a log link). Use this when you have no reason to expect the treatment effect to vary with age or bmi, and you just want to adjust for those covariates.

If you suspect the treatment effect depends on, say, age:

Show code 
m4 <- gam(y ~ tx + s(age, by = tx) + s(bmi) + ti(age, bmi) +
             sex + s(region, bs = "re"),
         data = dat, method = "REML")
plot_predictions(m4, condition = c("age", "tx", "bmi"))

s(age, by = tx) fits a separate smooth of age for each level of tx. The by term does not include the main effect of tx, which is why you still write tx + in the parametric part. Without that, the two age curves would be forced to have the same average level — almost never what you want. The interpretation: the difference between the two age-curves at any given age is the treatment effect at that age. With marginaleffects you would extract this with comparisons() or avg_comparisons(variables = “tx”, by = “age”). A small but important technicality: when tx is a factor with two levels, by = tx fits one smooth per level, each with its own smoothing parameter. This is usually what you want. If you wanted the two curves to share a smoothing parameter (more shrinkage, less flexibility per group), you would instead make tx an ordered factor and use the same syntax — mgcv then fits a reference smooth plus a difference smooth.

If treatment effect varies over the joint distribution of age and bmi — for example, treatment helps young, low-bmi patients more than older, high-bmi ones, in a way that does not factor cleanly into “depends on age” plus “depends on bmi”:

Show code 
m5 <- gam(y ~ tx + s(age, by = tx) + s(bmi, by = tx) +
             ti(age, bmi, by = tx) +
             sex + s(region, bs = "re"),
         data = dat, method = "REML")
plot_predictions(m5, condition = c("age", "tx", "bmi"))

Or, more compactly, replace the three by-smooths with a single tensor product:

Show code 
m6 <- gam(y ~ tx + te(age, bmi, by = tx) +
             sex + s(region, bs = "re"),
         data = dat, method = "REML")
plot_predictions(m6, condition = c("age", "tx", "bmi"))

This fits a separate age × bmi surface for each treatment arm. Powerful, but expensive in degrees of freedom — you need a lot of data, especially in the smaller arm, before this is identifiable.

Option 4: tx as a stratification variable (separate fits) A conceptually different approach: fit two GAMs, one per arm, and compare predictions. This is exactly what option 3 does internally, but doing it explicitly forces you to confront the sample size in each arm and is sometimes clearer to report. In a target trial emulation context option 4 is essentially the g-computation style; option 1 is the outcome regression with treatment indicator style.

A recommendation for your study For physiotherapy on work disability, I would suggest starting with option 1 to establish the average effect, then checking effect modification with a sequence of nested models:

Show code 
m1a <- gam(y ~ tx + s(age) + s(bmi) + ti(age, bmi) +
              sex + s(region, bs = "re"),
          data = dat, method = "ML")

m2a <- gam(y ~ tx + s(age, by = tx) + s(bmi) + ti(age, bmi) +
              sex + s(region, bs = "re"),
          data = dat, method = "ML")

m3a <- gam(y ~ tx + s(age, by = tx) + s(bmi, by = tx) + ti(age, bmi) +
              sex + s(region, bs = "re"),
          data = dat, method = "ML")

AIC(m1a, m2a, m3a)

Note the switch to method = “ML” — REML is for variance component estimation and is not strictly comparable across models with different fixed-effect structures. For final reporting, refit the chosen model with REML. A caveat I want to flag honestly: with claims data of any meaningful size, something will look like effect modification just from sampling variability across the basis dimension. Decide before fitting whether age/bmi effect modification is biologically plausible enough to spend the degrees of freedom on; if it isn’t, option 1 is the principled stopping point.

What it looks like in marginaleffects Whatever you choose, the inferential workflow stays the same:

14.3.1 bs="fs" vs bs="re" and how both differ from by=

There are three ways to mix a factor into a smooth, and they make different statistical assumptions.

  1. bs="re" — parametric random effect
Show code 
# random intercept by region
mre1 <- gam(y ~ s(age) + s(bmi) + sex + s(region, bs = "re"),
            data = dat, method = "REML")

# random slope of age within region
mre2 <- gam(y ~ s(age) + s(bmi) + sex +
                s(region, bs = "re") + s(age, region, bs = "re"),
            data = dat, method = "REML")

s(group, bs="re") is exactly equivalent to a Gaussian random intercept: levels are i.i.d. draws from N(0, σ²), with σ² controlled by one smoothing parameter. s(x, group, bs="re") gives random slopes (still parametric — linear in x). gam.vcomp(model) gives variance components on a familiar scale.

Note

translation of the last model to brms

mgcv term Meaning brms equivalent
s(age) smooth of age s(age)
s(bmi) smooth of bmi s(bmi)
sex parametric fixed effect sex
s(region, bs = "re") random intercept by region (1 \| region)
s(age, region, bs = "re") random slope of age by region (0 + age \| region) or (age \| region)

The first three lines are immediate. The last two need explanation.

Why s(..., bs = "re") becomes (... | region)

bs = "re" is mgcv’s way of embedding a random effect inside the GAM machinery. It treats the levels of the factor as draws from a Normal distribution with an estimated variance — exactly the lme4/brms random-effects formulation. So:

  • s(region, bs = "re") ↔︎ random intercept ↔︎ (1 | region)
  • s(age, region, bs = "re") ↔︎ random slope of age over region ↔︎ (0 + age | region)

The choice between (0 + age | region) and (age | region) matters:

  • (0 + age | region) — random slope only, no random intercept inside this term. This is the literal translation of s(age, region, bs = "re") on its own.
  • (age | region) — random intercept and random slope, with a correlation parameter between them estimated by brms.

Your mgcv model has s(region, bs = "re") and s(age, region, bs = "re") as two separate terms. The mgcv formulation is uncorrelated by construction: the random intercept variance and the random slope variance are estimated independently, with no correlation parameter between them. The faithful brms translation is therefore:

y ~ s(age) + s(bmi) + sex + (1 | region) + (0 + age | region) and equivalently y ~ s(age) + s(bmi) + sex + (age || region)

Two separate (... | region) terms is how lme4/brms syntax expresses uncorrelated random effects.

If you wanted to add a correlation between the random intercept and random slope (something mgcv cannot easily express):

y ~ s(age) + s(bmi) + sex + (1 + age | region)

what changes once you cross from mgcv to brms:

Priors. brms puts default priors on everything. They are usually reasonable but not always — for the smoothing variances on s(age) and s(bmi), and for the random-effect SDs, I would inspect them with prior_summary(m_brms) and consider weakly informative alternatives (student_t(3, 0, 2.5) is a common choice). Smoothing parameters become variances. mgcv’s λ is, mathematically, a ratio of variances. brms estimates those variances directly, with their own posterior distributions. You can extract the posterior of the smooth’s “wiggliness SD” from summary(m_brms) under Smooth Terms. Conceptually identical, parameterized differently. REML disappears. brms is fully Bayesian — there is no REML/ML choice. You sample the joint posterior over fixed effects, smooth coefficients, smoothing variances, and random-effect variances simultaneously. This is one reason brms is well-suited to GAMs with random effects: the partial-pooling logic is unified across all components. A caveat: random-slope models with a single covariate (age here) per group are sensitive to how age is centered and scaled. If age is on its raw scale (e.g., 18–80), the random-slope SD has a very different interpretation — and very different prior implications — than if age is centered or standardized. This matters more in brms than in mgcv, because brms’ default priors are scaled assuming reasonably standardized predictors. Centre age (subtract its mean, or subtract a reference value like 50) before fitting. The same goes for bmi.

14.3.2 bs="fs" — factor-smooth (random curves)

Show code 
# A separate SMOOTH of age for each region, sharing one wiggliness penalty,
# with the curve intercepts shrunk toward zero (random-effect-like).
mfs <- gam(y ~ s(age, region, bs = "fs") + s(bmi) + sex,
           data = dat, method = "REML")
plot_predictions(mfs, condition = c("age", "tx", "bmi"))

To incorporate treatment tx (we do not want shrinkage in tx) two possibilities:

  1. Interaction factor inside s(…, bs = “fs”)
Show code 
dat$tx_region <- interaction(dat$tx, dat$region, drop = TRUE)
#drop = TRUE removes factor levels that have 0 observations in the data
gam(y ~ tx + s(age, tx_region, bs = "fs") + s(bmi) + sex,
    data = dat, method = "REML")

One smooth of age per (tx × region) cell, all cells sharing one smoothing parameter. The fixed tx term carries the average treatment effect; the factor-smooth carries cell-level age curves. Coarse-grained but parsimonious. With binary tx and many regions, you halve the per-cell n.

  1. Decomposed structure
Show code 
gam(y ~ tx + s(age, by = tx) +
        s(age, region, bs = "fs") +
        s(bmi) + sex,
    data = dat, method = "REML")

  • tx — fixed average treatment effect.

  • s(age, by = tx) — fixed effect modification: the age curve for treated and untreated patients is allowed to differ in shape, with no shrinkage between arms.

  • s(age, region, bs = “fs”) — random regional deviations from the population age curve, with shrinkage across regions.

  • s(bmi) and sex — adjustment covariates.

This separates “what we want to estimate” (treatment effect, possibly age-modified) from “what we want to control for” (regional grouping with partial pooling). Each gets the correct statistical treatment.

Approach 1 forces the regional differences in the age curve to be separately estimated for each treatment arm, with the same smoothing parameter shared across the (now doubled) set of cells. That is wasteful: there is no reason to expect regional differences in how age affects work disability to themselves depend on whether the patient received physiotherapy. Approach 2 encodes the more plausible assumption — that regional variation is a single phenomenon, on top of which physiotherapy either does or doesn’t work — and uses the data more efficiently.

Caution

While with s() bs=“fs” is the right choice, with te() it becomes bs=“re”. The marginal bases inside te() (or ti(), t2()) must be univariate smoother classes — typically “tp”, “cr”, “ps”, or “re”. The “fs” class is itself a two-dimensional factor-smooth construction (a smooth crossed with a factor), so it cannot serve as a one-dimensional margin in a tensor product.

14.3.3 Putting it together

Show code 
m_full <- bam(
  y ~ tx                                              # exposure
    + sex                                             # parametric main effect
    + te(age, bmi, bs = c("cr","cr"), k = c(15, 15))  # smooth + interaction in confounders
    + s(age, by = sex)                                # sex-modified age curve
    + s(bmi, by = sex)                                # sex-modified bmi curve
    + ti(age, bmi, by = sex)                          # sex-modified interaction (optional)
    + s(age, region, bs = "fs", k = 8)                # region-specific age curves (shrunk)
    + s(bmi, region, bs = "fs", k = 8),               # region-specific bmi curves (shrunk)
  data    = dat,
  method  = "fREML",
  discrete = TRUE,
  nthreads = 4
)
  • te(age, bmi) over s(age, bmi) because the units differ.
  • by = sex (not bs="fs") because sex has 2 fixed levels we care about.
  • bs="fs" for region because levels are exchangeable and there are many.
  • k is a basis-size cap, not a forced edf — if gam.check() flags it, increase.
  • tx is a parametric coefficient. Its estimate is a conditional effect of treatment given the (flexibly modeled) confounder structure.

  1. The coefficient on tx is the conditional association, not necessarily the causal effect. If you want a marginal/population effect (ATE), use g-computation: predict counterfactual outcomes under tx=1 and tx=0 for everyone in the sample, then average and contrast. marginaleffects::avg_comparisons() plays nicely with gam/bam.

  2. Flexibility ≠ confounding control. No amount of spline flexibility fixes a missing confounder, post-treatment adjustment, or collider stratification. Draw the DAG first; then decide what to model flexibly.

  3. If tx has effect-modifiers among the confounders, you usually want it inside smooths too (e.g., s(age, by=tx)), then average appropriately. Otherwise the conditional tx coefficient assumes a constant treatment effect across age/bmi/region.

  4. Cross-fitting / DR estimators (TMLE, AIPW) are the more defensible route when you want a flexible nuisance model and valid inference for an ATE. Use the GAM as a learner inside tmle3, lmtp, or SuperLearner. Don’t expect a single bam() summary table to be a causal answer.

Considering that tx has 2 levels, could te(age, region, tx, bs=c(“tp”, “re”, “re”)) in principle give non-zero shrinkage to tx slope?

A random effect on tx estimates two coefficients — α_treated and α_untreated — as draws from N(0, σ²_tx). With sum-to-zero or equivalent constraints, this is one effective parameter: the contrast between arms. The shrinkage factor on that contrast is approximately

\[\text{shrinkage} \approx \frac{\sigma^2_{\text{within}} / n}{\sigma^2_{\text{within}} / n + \sigma^2_{\text{tx}}}\]

where σ²_within is the residual variance and n the per-arm sample size. The behaviour at the extremes:

  • Large σ²_tx (true treatment effect is big relative to within-arm variability): shrinkage factor → 0. The random-effect estimate is essentially the fixed-effect estimate. No meaningful regularisation.
  • Small σ²_tx (true treatment effect is weak): shrinkage factor → 1. The estimate is pulled hard toward zero.
  • σ²_tx exactly at zero: complete shrinkage; the model drops the tx contribution entirely.

So yes, between those extremes you get partial shrinkage. The problem is how σ²_tx is estimated.

14.3.4 Why this is unstable with 2 levels

With k levels of a factor, the random-effect variance σ² is estimated from k − 1 between-level differences. With k = 2, that’s one difference. REML’s estimator of σ²_tx is essentially built from a single number — the contrast α_treated − α_untreated — relative to within-arm noise.

Two practical consequences follow:

Boundary hits are common. REML variance estimators are bounded below at zero, and when there is little signal — or when the treatment effect is genuinely small — the estimate sits on the boundary, giving σ̂²_tx = 0 and complete shrinkage to zero. This is not a rare pathology; it is the typical behaviour when treatment effects are modest and within-arm variance is large.

The estimator behaves discontinuously. Because there is 1 df driving everything, σ̂²_tx flips between near-zero and large estimates depending on small perturbations of the data. The “amount of shrinkage” is therefore highly variable across resamples — a property you can verify by bootstrapping the model. Inference based on the resulting standard errors does not have nominal coverage near the boundary.

For nuisance grouping factors (regions, providers, hospitals), shrinking small estimated regional differences toward zero is a feature, because we usually have no scientific stake in any particular region’s deviation. With 50 regions, σ²_region is well-identified.

For the treatment exposure, the treatment effect is the estimand of the study. A model that quietly sets it to zero whenever the within-arm variance dominates is not regularising — it is biasing your causal estimate in a direction determined by sample size. In a target trial emulation framework, where the whole design is constructed to estimate the marginal effect of physiotherapy on disability outcomes, treating tx as random is conceptually misaligned with the estimand.

Random-effect treatment of factors is appropriate when (i) the levels can plausibly be regarded as exchangeable draws from some population and (ii) you have enough levels to identify the variance. Both fail for a 2-level treatment indicator.

So yes, shrinkage on tx can in principle be non-zero, and is occasionally meaningful. But the conditions under which it is non-zero are fragile, the estimator is discontinuous, and the resulting bias goes the wrong direction for a causal estimand.

14.4 Cross fitting and other modern stuff

The leap from “I have a flexible regression model” to “I have a valid causal estimate” is bigger than it looks. Suppose you want to estimate the average treatment effect (ATE) of physiotherapy on work disability outcomes. The classical workflow is:

  1. Fit a regression of outcome on treatment, adjusted for confounders.

  2. Read off the coefficient on treatment, with its standard error and confidence interval.

This works, more or less, when the regression is correctly specified — when the functional form of every confounder–outcome relationship is right. With a GAM you have done much better than a misspecified linear model, but you have introduced a new problem: you cannot trust the standard error on the treatment coefficient anymore.

The technical reason: penalised splines are biased estimators of the conditional mean. The penalty trades bias for variance to fit better overall, but the bias does not vanish at root-n rates. When you plug a biased nuisance estimate into a downstream effect estimate, the bias contaminates your effect estimate too. Confidence intervals from summary(gam_fit) on the treatment term are therefore not what they claim to be.

The same problem afflicts machine-learning regressions (random forests, gradient boosting, neural nets) used as nuisance models. The doubly robust / cross-fitting machinery was built specifically to recover valid inference in this setting.

14.4.1 The doubly robust idea: AIPW

The augmented inverse probability weighted (AIPW) estimator combines two models:

  • An outcome model: μ̂(x, a) = E[Y | X = x, A = a]. The fitted values predicting outcome from confounders and treatment.
  • A treatment model (propensity score): π̂(x) = P(A = 1 | X = x). The probability of receiving treatment given confounders.

The AIPW estimator of the ATE has the form

\[\widehat{\text{ATE}} = \frac{1}{n} \sum_{i=1}^{n} \left[ \hat{\mu}(X_i, 1) - \hat{\mu}(X_i, 0) \right] + \text{IPW correction term}\]

The correction term, intuitively, fixes the residual bias in μ̂ using information from π̂. The “doubly robust” name refers to a remarkable property: the estimator is consistent if either μ̂ or π̂ is consistent — you do not need both. This is reassuring because in real applied work neither model is exactly right, but at least one usually captures the bulk of the structure.

That property alone is not enough for valid inference, however. To get confidence intervals that work, you also need a procedure that prevents the nuisance models from “seeing” the data they are evaluated on.

14.4.2 Cross-fitting

If you fit μ̂ and π̂ on the same data you use to compute the AIPW estimate, the fitted values are over-fitted, which biases the AIPW estimator and shrinks its standard errors. Standard regression has the same issue but at a manageable rate; flexible learners (splines included, ML methods more so) overfit at rates that break the inferential guarantees. Cross-fitting solves this by splitting the data into K folds (typically 5 or 10), and for each fold:

  1. Fit μ̂ and π̂ on the other K−1 folds.

  2. Use those fitted models to predict on the held-out fold only.

  3. Compute the AIPW contributions on the held-out fold using those out-of-fold predictions.

Average across folds, and the resulting estimator has root-n convergence and asymptotically normal sampling distribution under conditions that allow the nuisance models to converge at much slower rates (n^(1/4) suffices). This is the core insight of double/debiased machine learning (Chernozhukov et al., 2018) — the same machinery underlies TMLE.

14.4.3 TMLE versus AIPW

TMLE — targeted maximum likelihood estimation (van der Laan & Rose) — is a refinement of the same idea. Where AIPW adds a correction term to the outcome-model average, TMLE updates the outcome model itself using information from the propensity score, and then takes the simple average from the updated model. The two estimators have the same asymptotic properties; TMLE often has slightly better finite-sample behaviour and respects bounds on the outcome (probabilities stay in [0,1] etc.). For most applied purposes the choice between them is taste.

14.4.4 SuperLearner: the ensemble layer

Both AIPW and TMLE need μ̂ and π̂ from somewhere. You could fit each with a single model — a GAM, say, or a random forest. SuperLearner is a separate idea: rather than commit to one learner, fit several candidate models (a GLM, a GAM, a random forest, a gradient-boosted tree) and let cross-validated stacking weight them into an ensemble. The ensemble is then plugged into AIPW/TMLE as the nuisance estimator. This is a hedge against learner misspecification and is the default workflow in the tmle3 / sl3 ecosystem.

Your GAM lives inside this stack as one candidate among several. It is a good candidate — splines are excellent for moderately complex confounder–outcome relationships in epidemiology. But you no longer rely on it to be uniquely correct.

14.4.5 R packages

Three modern packages in R, each with a slightly different focus:

  • tmle3 / sl3 (van der Laan group). Most general; supports AIPW, TMLE, longitudinal extensions. Steep learning curve.
  • lmtp (Williams, Díaz). Specialised for longitudinal modified treatment policies — closest to your TTE setting if you want to estimate effects of treatment strategies that depend on covariate history. Has built-in SuperLearner integration.
  • DoubleML (Bach et al.). Implements DML with cross-fitting; cleaner API for static settings; less focused on causal vocabulary, more on partial-effect estimation.

A skeleton call in lmtp looks like this:

Show code 
library(lmtp)

learners <- c("SL.mean", "SL.glm", "SL.gam", "SL.ranger")

ate <- lmtp_tmle(
  data       = dat,
  trt        = "tx",
  outcome    = "y",
  baseline   = c("age", "bmi", "sex", "region"),
  outcome_type = "continuous",
  learners_outcome = learners,
  learners_trt     = learners,
  folds = 10
)

ate    # ATE estimate, SE, CI from cross-fitted influence function

Under the hood: 10-fold cross-fitting; each fold’s μ̂ and π̂ built from a SuperLearner ensemble; TMLE update; influence-function-based standard error. The summary method on the result gives a properly calibrated 95% CI for the ATE — the kind of summary that gam.check() cannot.

Warning

Computational cost is high. With 10 folds and a SuperLearner library of 4–5 learners, expect runtimes of minutes to hours on claims-data-sized problems. Plan accordingly.

These methods do not magic away unmeasured confounding. They give you valid inference under your causal assumptions (exchangeability, positivity, consistency). They do not check those assumptions for you. The DAG work you have already done is exactly as load-bearing as it was for IPW; this is just better machinery downstream.

The TTE design layer comes first. For your physiotherapy study, the immortal-time handling, grace periods, and target-trial protocol determine the estimand. AIPW/TMLE is a way to estimate that estimand more efficiently and with better-calibrated inference; it is not a substitute for the design itself. lmtp is built with sequential treatment in mind and is probably the natural home for your analysis once the TTE specification is finalised.

Do not expect a single number to be the answer. The whole point is that valid causal estimation requires layered choices — design, identification, nuisance estimation, inference — and cross-fitted DR estimators cleanly separate those layers. A bam() summary table conflates them, which is why I would not present its treatment p-value as a causal answer to a referee.

For an entry point into the literature: Causal Inference: What If (Hernán & Robins, free online) for the identification side; the TMLE book (van der Laan & Rose, Targeted Learning) for the estimation side; and the original double-ML paper (Chernozhukov et al., 2018, Econometrics Journal) for the cross-fitting argument.

14.5 Recap: GAM model structures with treatment, factors, and smooths

Two principles to anchor everything:

Principle 1. tx is the estimand of interest. It should not enter the model in any way that shrinks the treatment-effect contrast itself: not as bs = "re", not as an "re" margin in a tensor product. Including tx as a level-defining factor in bs = "fs" is acceptable — it pools the roughness of the two age curves, not the contrast between them — but be aware that with only two levels you are using a tool designed for many.

Note

bs = "fs" is a different beast from bs = "re". s(age, tx, bs = "fs") does not shrink the treatment effect itself. It does shrink the difference between the two age-curves — which is a different quantity, and one you may or may not want to shrink.

s(age, tx, bs = "fs") produces one smooth of age per level of tx — two curves, sharing a single smoothing parameter. The shrinkage that this term applies operates on the wiggliness of those two curves and on their level-shifts from a common centre. It does not pool the two curves’ contrasts toward zero in a way that biases the estimated treatment effect at any given age. If the treated and untreated arms have genuinely different age curves, bs = "fs" will recover that difference — the smoothing parameter regulates how rough each curve is allowed to be, not how far apart the two arms can sit. The treatment effect at age = a, defined as the difference between the two curves at that point, is estimated as flexibly as the data allow. This is the crucial contrast with bs = "re" on tx, which estimates a variance σ²_tx and shrinks the contrast α_treated − α_untreated proportionally. bs = "fs" has no such variance on the contrast — what it has is a single smoothing parameter on curve roughness, applied identically to both arms.

Warning

The “fs” smooth is not centred (no sum-to-zero constraint), which means it carries its own intercepts for each level of tx. Mathematically this looks fine. Practically, it raises two issues:

Issue 1: identifiability with only two levels. The “fs” construction was designed for many factor levels — patients in a longitudinal study, hospitals in a multicentre trial — where partial pooling across levels is the point. With two levels (treated, untreated), there is no other level to pool toward; the “fs” structure technically still applies, but you are using a tool built for k large to handle k = 2. mgcv will fit it. The result is usually similar to s(age, by = tx) with a shared smoothing parameter across the two arms, which is sometimes desirable and sometimes not.

Issue 2: the constraint structure interacts oddly with the parametric tx term. Because bs = "fs" carries its own per-level intercepts, you do not need (and should not include) tx + as a parametric main effect alongside it — that would be redundant and could create collinearity warnings. This breaks Principle 2 from the recap. So the typical call is just s(age, tx, bs = "fs") + s(bmi) + sex, with no separate tx term.

14.6 Where this differs from s(age, by = tx)

s(age, by = tx) + tx s(age, tx, bs = "fs")
Per-arm age curves Yes Yes
Smoothing parameter One per arm One shared across arms
Centring Each smooth centred (sum-to-zero) Not centred
Need tx + main effect? Yes (carries the level shifts) No (smooths carry their own)
Treatment-effect contrast shrunk? No No
Wiggliness pooled across arms? No Yes

The practical difference: bs = "fs" forces the two age curves to have the same degree of smoothness. by = tx lets one arm’s curve be much wigglier than the other if the data demand it. For a physiotherapy intervention where you might expect both arms to follow age in qualitatively similar ways (most of the curve shape is determined by underlying age-related disability risk, with a treatment offset on top), the shared smoothing parameter is a plausible regularisation. For situations where the treated arm might respond very differently with age, by = tx is more flexible.

In your TTE setting, I would still default to tx + s(age, by = tx) because the fixed by form is the simplest, most transparent encoding of “two age curves, freely estimated.” bs = "fs" becomes attractive when you have many treatment-defining factor levels (multiple physiotherapy intensities, say, or treatment timing categories) where pooling roughness across levels is genuinely informative. With binary tx, both work; by = tx is the more standard choice and produces a cleaner summary table.

Principle 2. When a factor is crossed with a smooth via by =, the smooth is centred (sum-to-zero), so the level-specific intercept must come from a parametric main effect. Always include the factor as a main effect alongside s(x, by = factor). This rule does not apply to bs = "fs" factor-smooth interactions or to bs = "re" random-effect margins, which are not centred — those terms carry their own intercepts.

It depends on where you want shrinjage, wether to add main effects with bs=“re”: Additive main effects are not redundant with te(…, bs=“re”), because te() (unlike ti()) already contains its marginal main effects. That is why mgcv adds identifiability constraints when you write s(x) + s(y) + te(x, y). So whether main effects appear additively isn’t about whether they’re “in” the model — they always are. The question is where the penalty sits.

Without + sex + age_group, in the model te(year, bmi, sex, age_group, bs=c(“tp”, “tp”, “re”, “re”)) the marginal effect of sex/age_group lives entirely inside te() and is subject to the bs = “re” random-effect penalty — i.e., shrunk toward zero with the same variance component as the interaction deviations. With + sex + age_group, the additive term carries the unpenalised fixed-effect main effect; the te() carries the shrunk interaction deviations only. This is the standard te = main + ti decomposition. So the 2nd structure is closer to what you want: don’t shrink the main effect of sex toward zero just because you also want shrunk interactions.

1. tx + s(age, by = tx)

Two independent age curves, one per treatment arm, each with its own smoothing parameter. The fixed tx term provides the level-specific intercepts that the centred by = smooths cannot. This is the workhorse for “does the treatment effect depend on age?”. Marginaleffects extracts the answer cleanly with comparisons(model, variables = "tx", by = "age").

2. s(age, region, bs = "fs", xt = "cr")

A per-region age curve, with cubic regression splines as the per-level basis (the xt = "cr" argument controls the marginal basis; the default is "tp"). All region-curves share one smoothing parameter, which is what gives this term its random-effect character: regions with little data are pooled toward a common shape. Note: bs = c("cr", "fs") is not valid s() syntax — bs in s() is one string, and the marginal basis for an "fs" smoother is set via xt, not via a vector to bs.

3. te(age, bmi, region, bs = c("tp", "tp", "re"))

Treats region as a random effect and shrinks the treatment contrast toward zero.

4. te(age, bmi) + sex + s(region, bs = "re")

Clean baseline structure with no treatment. A joint smooth surface of age × bmi (main effects and interaction baked in, with a separate smoothing parameter per margin so rescaling either covariate is harmless), sex as parametric, region as a random intercept. Good starting point for an exploratory adjusted model. To add treatment, prefix with tx + and consider whether s(age, by = tx) or other modifiers are warranted.

5. s(age) + s(bmi) + ti(age, bmi) + sex + s(region, bs = "re")

The ANOVA-style decomposition of te(age, bmi). Main effects of age and bmi enter as separate smooths; the pure interaction enters through ti(), which strips the marginal main effects out. The advantage over te(age, bmi): you can read off whether the interaction matters from the summary() table — its EDF, p-value, and contribution are isolated from the main effects. The fitted prediction surface is essentially the same as te(), so for marginaleffects-only workflows the two are interchangeable; for inferential reporting on the interaction, prefer this form.

6. s(age, region, bs = "fs") + s(bmi) + sex

Per-region age curves with shared smoothing parameter, plus main effects of bmi and sex. No global age curve, so each regional curve is a stand-alone fit; if you want regional curves to be deviations from a common shape, write s(age) + s(age, region, bs = "fs") instead. To add treatment under principle 2 (treatment as fixed), the natural extension is tx + s(age, by = tx) + s(age, region, bs = "fs") + s(bmi) + sex.

7. te(age, bmi, region, bs = c("tp", "tp", "re")) + sex

3-way smooths require dense data in every (age, bmi, region) neighbourhood you want to interpret.

14.7 A practical hierarchy for TTE

If you are choosing among these for the physiotherapy study, the progression I would suggest is:

tx + s(age) + s(bmi) + sex + s(region, bs = "re") — establish the average treatment effect with a sensible adjusted baseline.

tx + s(age, by = tx) + s(bmi) + sex + s(region, bs = "re") — allow the treatment effect to vary smoothly with age, the most plausible single source of effect modification.

tx + s(age, by = tx) + s(bmi, by = tx) + ti(age, bmi) + sex + s(region, bs = "re") — allow effect modification by both age and bmi independently, while keeping the age × bmi interaction common across arms.

tx + s(age, by = tx) + s(age, region, bs = "fs") + s(bmi) + sex — fixed treatment effect with smooth age modification, plus partially-pooled regional deviations in the age curve.

Compare with AIC() on models fitted with method = "ML"; refit the chosen one with method = "REML" for final reporting; and pass it to marginaleffects for the actual treatment-effect quantities. And if the inference on the treatment effect itself needs to be defensible to a sceptical reviewer, that is when AIPW/TMLE with the GAM as a SuperLearner candidate enters the picture.
