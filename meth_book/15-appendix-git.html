15  Appendix 6 Git

Git is a software on your computer which tracks changes to your code files and saves snapshots of your project whenever you ask it to. It’s free, open source, and runs entirely on your machine. GitHub is a Microsoft cloud service that stores your Git repositories. It allows you to share them, access them remotely and back up lost files on your hard drive. For work with sensitive data a good alternative to Github is Codeberg (https://codeberg.org), which is run by a German nonprofit. They do not sell your data and do not train AI on your code.

  1. Create an account on github.com

  2. Create a new repository on Github: New repository → name it → Create. Copy the URL it gives you.

3.Set up git on your machine in terminal: git --version checks if git is already installed. Instructions: https://git-scm.com/install/

  1. configure your name and email (you do it only once) in terminal:

git config --global user.name "Your Name"

git config --global user.email "your@email.com"

  1. initiate a repository (repo) by navigating in the terminal to your project folder and run:git init Git creates a hidden folder .git inside your project. That folder is the history of your project. Your project is now being tracked.

  2. commit your changes. Two lines:

git add .

git commit -m "Initial setup"

git add . includes all your files in the next snapshot (hence the dot). You can also add specific files with git add filename if you only want to commit some changes.

git commit -m "message" saves the snapshot with your commit message.

git log prints your commit with a timestamp.

  1. Push to cloud service (like Github)

To back it up to GitHub (or wherever), you need to create an empty repository there first, then connect your local one to it.

On GitHub: click the “+” icon at the top right, choose “New repository,” give it a name, and make sure you do NOT check “Add a README” (you want the empty repository). Copy the URL it gives you.

Then run these:

git remote add origin https://github.com/yourusername/your-repo.git

git push -u origin main

The first line tells local Git where remote copy is. git push -u origin main uploads your commits. -u sets this as the default remote for, so after the first push you just run git push.

The idea is to Repeat add → commit → push whenever you finish a task.

Create a file called .gitignore in your project root. This file tells Git which files and folders not to follow. Passwords, API keys, large files, etc. Everything committed and pushed to a remote is there forever!

RStudio has a built-in Git panel — you don’t have to use the terminal at all. see https://happygitwithr.com/rstudio-git-github

  • File → New Project → Version Control → Git — paste your GitHub repository URL

  • The Git tab appears in the top-right panel

  • Check boxes next to changed files (= git add)

  • Click Commit, write a message, click Commit again (= git commit)

  • Click Push (= git push)

  • Commit before you do anything important. If what you do fails, you can undo with one command: git reset --hard HEAD.

  • Commit after successful changes to code. Each commit is a checkpoint you can return to.

Every commit message is documentation. Months later, whether it’s human or an AI agent, commit messages make the history useful.

to read your commit history is as important as knowing how to write it. These are the commands I use most:

git log Prints all commits, newest first

git log --oneline shows a compact view

git show HEAD what changed in the last commit?

git diff abc1234 def5678 what changed between these commits?

git show --stat abc1234 which files changed in a commit?

When Claude Code starts a debug session it reads back through the recent commits. Here commit messages pay off.

Commit history is also on GitHub’s web interface for pushed code. In your repo click “N commits” at the top of the file list.

15.1 If you Work alone push directly to main

Commit often, push regularly.

A branch is a separate line of development that doesn’t affect main until you merge it back. To create one:

git checkout -b experiment makes a new branch called experiment and switches to it

git add .

git commit -m "try new xxx approach"

git checkout main

git merge experiment merge the branch back to main

git branch -D experiment alternatively, just delete the branch, it dissapears.

Branching is especially useful when you’re tasking AI. You give the agent a branch to work on, let it build and commit freely, then review before merging.

15.2 Team work (with AI)

  1. Create a branch for your part of work

  2. Commit to that branch

  3. Push the branch to GitHub: git push origin branch-name

  4. Open a Pull Request (PR) on GitHub to merge your branch into main

  5. Someone else reviews it and approves

  6. Merge to main

The PR review protects main from broken code. The other pair of eyes might catch a bug, suggest a better approach, or ask a clarifying question. For PR you need to fill in the description field, which in turn becomes documentation: why this approach, what I considered and rejected. That context is useful later to understand what was done and why. When AI reads your repo, a PR description gives it context the commit message doesn’t.

When Claude Code starts a session, one of its first actions is reading repository context: the file structure, the current state, and often the recent commits. Reading recent commits helps it understand how you name things, how you structure files, what you’ve already tried. Good history accelerates the agent’s work. Messy history slows it down. Think about commit message as a note to someone who has no other context.

A merge conflict happens when there are two different versions of the same file and Git does not know which change to keep. Git marks the conflicting lines in the file, you open it, decide which version is correct, delete the conflict markers, and commit.

Some commands

git init # Start tracking a folder git status # See what changed since last commit git add . # Stage all changes git add filename.py # Stage one specific file git commit -m "message" # Save a snapshot git push # Upload to remote git pull # Download from remote git log # See commit history git log --oneline # Compact history view git diff # See exactly what changed (unstaged) git diff --staged # See what’s staged for next commit git show HEAD # See the most recent commit in detail git checkout -b branch-name # Create and switch to new branch git checkout main # Switch back to main git merge branch-name # Merge branch into current branch git branch -D branch-name # Delete a branch git reset --hard HEAD # Undo all uncommitted changes (careful) git reset --hard HEAD~1 # Undo last commit AND its changes (careful) git revert HEAD # Undo last commit but keep the history

15.3 working in Terminal

In R getwd() gives you “/home/yourname/Documents/R/my_project”. Paste this path to Terminal cd path.

Opening the Terminal in Windows: Search for PowerShell in the Start menu. In mac: Cmd + Space → type “Terminal”

commands

pwd — Where am I? pwd /home/yourname/Documents/R/my_project

ls — What’s in here? ls data/ analysis.R README.md

cd — Move somewhere cd /home/yourname/Documents/R/my_project

To go up one level: cd ..

AI tools need API keys. You pass them as environment variables.

When you launch your terminal, you will see a prompt that often looks a little like this:

Mac:~$ This is the main interface to the shell which tells you that you are on the machine called Mac and that your current working directory is ~ (a.k.a. “home”). The $ says that you are not the root user. At this prompt you can type a command. The most basic command is to execute a program (with arguments):

Mac:~$ echo hello hello

Shell executed the program echo with the argument hello. The echo simply prints out its arguments. The shell parses the command by splitting it by whitespace, and then runs the program indicated by the first word, supplying each subsequent word as an argument to that the program. If you want to provide an argument that contains spaces or other special characters, quote the argument with ’ or “.

An important command is man (manual), which looks up more information about any command. You can also usually get a short version of the help by passing –help as an argument to most commands.

cd, or “change directory”: You pass it a path, and that path becomes your current working directory. You’ll also see the working directory reflected in the shell prompt:

missing:~$ cd /bin missing:/bin$ cd / missing:/$ cd ~ missing:~$

If you don’t know where you are, pwd gives the current working directory. The current working directory allows to use relative paths. Absolute paths start with / and gives the full set of directories from the root of the file system (/). Relative paths are relative to the current working directory. In a relative path (not starting with /), the first path component is looked up in the current working directory, and subsequent components traverse as usual. For example:

Mac:~$ cd / Mac:/$ cd bin Mac:/bin$

Special components: . is “this directory”, and .. is “the parent directory”, so

Mac:~$ cd / Mac:/$ cd bin/../bin/../bin/././../bin/.. Mac:/$ You can usually use absolute and relative paths interchangeably for any command argument, just keep in mind what your current working directory is when using a relative one!

If the shell is asked to execute a command, it consults an environment variable called $PATH that lists which directories the shell should search for programs when it is given a command:

Mac:~$ echo $PATH /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

Mac:~$ which echo /bin/echo Mac:~$ /bin/echo $PATH /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

When we run the echo command, the shell sees that it should execute the program echo, and then searches through the :-separated list of directories in $PATH for a file by that name. We can find out which file is executed for a given program name using the which program. We can also bypass $PATH entirely by giving the path to the file we want to execute.

we can determine all the programs we can execute by listing the contents of all the directories on $PATH. We can do this by passing a given directory path to the ls program, which lists files:

Mac:~$ ls /bin

cat file prints the contents of file. sort file prints out the lines of file in sorted order. uniq file eliminates consecutive duplicate lines from file. head file and tail file print the first and last few lines.

grep pattern file finds lines matching pattern in file. Pattern is a regular expression. You can also specify a directory instead of a file (or leave it off for .) and pass -r to recursively search all the files in a directory.
